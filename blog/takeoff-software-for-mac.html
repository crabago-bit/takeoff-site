Takeoff software for Mac:
the honest 2026 picture

The construction software industry has spent a decade telling Mac users to buy a Windows laptop. Here's what's actually available on a Mac today, what "runs in a browser" really means, and what native buys you.

How the Mac gap got this bad

If you estimate on a Mac, the last few years have been a series of doors closing. Bluebeam discontinued Revu for Mac in 2023 — the same year it stopped selling perpetual licenses. The Revu iPad app followed, retired on December 31, 2025. PlanSwift and On-Screen Takeoff never ran on macOS at all; both are Windows-only, and PlanSwift is reportedly still a 32-bit application.

The industry's standard answers have been: run Windows in a virtual machine, keep a separate PC for estimating, or use a browser tool. The first two mean buying and maintaining a second operating system to do your job. The third deserves a closer look, because "works on Mac" and "is Mac software" are not the same claim.

Browser tools run on a Mac. That's not the same thing.

STACK, Togal.AI, and Kreo all run in Safari or Chrome, so technically they work on a Mac — same as on a Chromebook. They're capable products (we compare them honestly in our alternatives roundup), but a browser tab has structural limits no amount of web engineering removes:

  • Connectivity is a hard dependency. None of the three has an offline mode. On a jobsite with bad signal, in a trailer, or on a flight to a bid review, a browser takeoff tool is a blank tab. Lag and jobsite connectivity are the top user complaints about STACK for exactly this reason.
  • Performance ceilings. A 400-sheet hospital set pushes a browser's memory and rendering model hard. Native apps talk to the GPU and filesystem directly; tabs don't.
  • File handling. Native apps open PDFs from Finder, double-click, drag-and-drop, and work with local folders. Browser tools require uploading your sets to someone's cloud before you can draw a single line — and your archive lives there afterward.
  • The little things. System shortcuts, real menus, multi-window layouts, working when your session cookie expires mid-takeoff. None fatal alone; together they're the difference between software and a website.
The quick test: turn off Wi-Fi and try to measure a sheet. If the answer is a spinner, you don't have Mac software — you have a subscription to someone else's computer.

What "native" actually buys you

Native isn't a purity badge; it's a set of concrete behaviors. A native Mac takeoff app installs from a .dmg and lives in your dock. It opens local files instantly and renders large sheets with the machine's actual hardware — an M-series MacBook is an absurdly fast PDF machine when software is allowed to use it. It keeps working when the internet doesn't: Groundwork Takeoff is offline-first with a 14-day offline grace period, meaning you can measure, count, and price for two weeks without a connection and sync when you're back. And it treats your files as yours — your plan sets don't have to live in a vendor's cloud to be usable.

Real-time collaboration still works when you are online; offline-first means connectivity is an enhancement, not a requirement. That's the inversion browser-only tools can't offer.

The iPad question

Worth a separate note, because Bluebeam's iPad retirement stranded a real workflow: field verification. Walking a site with the drawings, confirming a dimension, marking what changed — that job wants a tablet, not a laptop. Groundwork Takeoff runs on iPad as a home-screen app, and because collaboration is real-time, a markup made on site appears in the office copy as it happens, with every change tracked in the Revision Log. It's the same project, not an export — which is the part that made losing the Revu iPad app hurt in the first place.
